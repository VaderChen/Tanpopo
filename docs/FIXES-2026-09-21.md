## 操作與相容性

- GGUF 刪除保留同目錄的其他權重、分片、mmproj、Draft 與 metadata。這些資產可能共用；目前沒有能證明完整套件所有權的 manifest，因此不會連帶刪除。
- 持久登入紀錄位於 `settings.json` 所在目錄的 `sessions.json`，只保存 token 雜湊及到期時間，檔案權限 0600。舊版沒有伺服器紀錄的 Cookie 需重新登入。紀錄損毀或無法讀取時啟動回報錯誤，無法保存撤銷時登出回報失敗。
- ZIP 自動更新需要可連線至 GitHub，以及對應發布 asset 的 SHA-256。摘要來源固定為已安裝程式的建置設定；上傳包的 `update_repository` 不會改變信任根。離線、自製未發布、缺少摘要或已被重新壓縮的 ZIP 都無法通過自動更新。此機制信任 GitHub HTTPS 與指定 repository 的發布權限，沒有宣稱具備離線數位簽章。GitHub 的摘要欄位依據 [Release assets API 文件](https://docs.github.com/en/rest/releases/assets)。
- 更新目標必須支援本次新增的啟動確認協定；不支援的舊版或程序未就緒時會判定失敗。完整替換及復原流程仍須在 Linux 實機驗收。
- 遠端圖片可設定 `--image-allowed-origin https://images.example.com`，可重複指定。授權代表信任該主機與 DNS，請使用可控的圖片服務；預設沒有任何遠端授權。URLSession 不共用 Cookie、憑證或快取，閒置請求上限 15 秒、總資源期限 30 秒。
- 新的 MLX 參數需要重新編譯 Runtime。開發啟動器會偵測來源更新；正式使用需重新建置發布包。本次未替換正在使用的 Runtime 或既有發布包。
