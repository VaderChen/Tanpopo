## 問題與修正證據

| 問題 | 原因與影響 | 修正與驗證 |
| --- | --- | --- |
| R2-01 帳密更新失敗仍改變登入狀態 | 撤銷憑證、寫入設定與更新記憶體分開執行；儲存失敗時可能保留錯誤帳號或使原登入失效，登入也可能插入提交過程。持久登入寫入失敗被誤報為帳密錯誤 | 在同一個 Session 鎖內完成撤銷保存與設定提交，提交失敗還原原登入紀錄；成功後才套用記憶體狀態。登入儲存失敗回傳 HTTP 500，錯誤密碼維持 401，失敗不核發 Cookie。以磁碟失敗、設定提交失敗、持久紀錄重載與並行登入測試驗證 |
| R2-02 分段下載計算溢位與過量配置 | 依遠端宣告的檔案長度一次配置所有區段，`Int64.max` 可觸發 `makeslice: cap out of range`，大量區段也會耗盡記憶體 | 改為逐段產生工作，佇列容量依工作執行數設定；區段終點與數量計算避免加法溢位，取消時等待產生器結束。原先重現 panic 的最大整數測試已通過，既有分段下載測試通過 |
| R2-03 更新重啟後失去互斥與狀態停滯 | 更新鎖只在 Manager 記憶體內，Helper 尚在執行時管理服務重啟可能接受另一個更新；Helper 結束後狀態可能永遠停在準備中 | 使用安裝目錄旁的持久鎖檔，由 Helper 繼承相同檔案描述符。鎖檔不刪除，避免不同 inode 繞過互斥；子程序由 Wait 回收，狀態以跨程序鎖判斷是否仍在執行。以真實子程序、父端關閉描述符、安裝目錄替換及 Manager 重建測試驗證 |
| R2-04 NetPass 停止與重啟競態 | 舊程序清理可能與新程序啟動交錯，誤刪新程序設定；服務 context 已取消仍可啟動，主服務也未同步等待 NetPass 清理 | 序列化啟停生命週期，停止等待程序 Wait 與清理完成，已取消的服務拒絕啟動。主服務關閉流程加入 NetPass，與其他清理各自使用獨立期限；另修正錯誤狀態的無鎖讀取。以不連網的假 NetPassClient 執行 12 輪並行啟停並檢查設定與程序狀態，race 檢查通過 |
| R2-05 模型刪除與啟動之間存在空窗 | API 先取得狀態再刪除檔案，其間 Start 可能開始使用同一模型；轉換快取同樣缺乏共同互斥 | 模型及轉換快取刪除在 Runtime Manager 的啟停鎖內重新確認使用狀態並完成操作；統一 Target、Draft、mmproj 與 MLX 目錄的比對並正規化路徑。等待鎖後切換為執行中模型的測試確認拒絕刪除；HTTP Smoke 確認兩個端點皆回傳 409，模型檔仍存在 |
| R2-06 部分圖片處理失敗留下暫存檔 | 清理 defer 原本在整份訊息轉換成功後才建立，第二張圖片失敗會留下第一張；暫存檔也未明確限制權限 | 每個請求使用獨立的私有暫存目錄，在解析訊息前即註冊清理。目錄 0700、檔案 0600，文字請求與超限圖片不建立目錄；deinit 提供清理後援。Swift 驗證後續圖片失敗、錯誤退出、權限及無圖片情境 |
| R2-07 更新準備提前變更共用 Runtime | installer 預設更新共用 `llama.cpp/current`，應用程式替換失敗時只回復主程式目錄，Runtime 版本可能留在新版 | 更新 Helper 將 `LLAMA_CPP_INSTALL_DIR` 指向暫存發布目錄內的 `llama.cpp`，Runtime 與相對 current 連結一同切換或回復。以假 installer 驗證既有共用 Runtime 不變，發布目錄改名後新 Runtime 連結仍有效；另比對現有 installer 與 Runtime 搜尋路徑 |

## 行為與相容性

- 帳密設定提交失敗會嘗試還原原持久登入紀錄。若連還原也無法寫入，採取撤銷登入並明確回報錯誤，避免宣稱尚未持久化的登入狀態已成功還原。
- Linux 更新在安裝目錄旁保留 `.<安裝目錄名稱>.update.lock`。這是互斥用的空檔案，不能在更新中刪除；程序結束會釋放作業系統鎖，不需要刪除檔案。
- 新的 ZIP 更新會在應用程式目錄中保有自己的 llama.cpp Runtime。系統套件安裝或權限調整仍屬 installer 的外部副作用，這項修正沒有宣稱可回復作業系統套件。
- 暫存圖片在正常結束、可處理的錯誤與取消路徑清理；程序遭強制終止或檔案系統拒絕刪除時，不能保證完成清理。
