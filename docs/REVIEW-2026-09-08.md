# 2026-09-08 三輪程式審查與回歸驗證

## 範圍與結論

本次以 LlamaLoader／Tanpopo 為範圍，依序完成三輪「檢視、分析、修正、測試」。涵蓋 Go API 與設定儲存、網頁串流、MLX 請求邊界、更新套件驗證，以及桌面介面與建置腳本檢查；並未修改其他專案。

已修正串流未完成卻被當成成功、代理端送出失敗後繼續讀取、設定並行更新遺失、設定切片共用、清理腳本穿過父目錄符號連結，以及 MLX 設定數值截斷等問題。所有本次執行的最終回歸檢查通過。這不代表已完成所有實機情境的驗收，未涵蓋項目列於文末。

## 第一輪：API 與串流生命週期

### 問題與修正

- **串流中斷誤判完成**：原本只要收到部分文字，HTTP EOF 就可能被視為成功。新增獨立串流讀取器 `website/assets/chat-stream.js`，要求完整的 SSE `[DONE]` event；未完成、格式錯誤或 Runtime 錯誤皆回報失敗。
- **讀取器與畫面排程未確實清理**：正常完成、讀取失敗、錯誤 event 及回呼異常，統一取消 reader 並釋放鎖；畫面更新排程也在 `finally` 中清除。
- **Flush 錯誤被忽略**：Go 代理端使用 `http.ResponseController.Flush()` 取得送出錯誤，失敗後停止讀取上游，由既有請求結束流程關閉上游 Body。
- **每次請求建立的 transport 殘留閒置連線**：請求結束時關閉該 transport 的 idle connections，不等待閒置逾時。
- 補齊新錯誤訊息的既有語系翻譯，更新聊天頁面的 script 版本與載入順序。

### 驗證

修正前，`TestProxyRuntimeChatStreamStopsOnFlushFailure` 在第一次與第二次 Flush 失敗情境均重現多餘的上游讀取；修正後通過，原有 SSE 原樣轉送測試也通過。

新增 7 項 JavaScript 串流測試，涵蓋逐 byte UTF-8／CRLF 分段、思考內容與 usage、完整 DONE、缺少 DONE、不完整尾端 event、錯誤 event、JSON 解析失敗、讀取失敗及回呼異常。這些情境均驗證結束與資源清理行為。

## 第二輪：設定交易與並行儲存

### 問題與修正

- **讀取後整份覆寫會遺失更新**：不同 API 各自執行 Get／Save 時，收藏、校準紀錄及其他設定可能被舊快照覆寫。新增 `config.Store.Update`，在同一把鎖內完成讀取、修改、驗證、寫檔及記憶體更新；設定、常駐模式、收藏新增／刪除與校準保存均改用此入口。
- **落盤與記憶體更新順序可能不一致**：原本 Save 的鎖只保護最後的記憶體指派。現在 Save 的整個保存流程一併序列化，只有成功寫入才更新記憶體。
- **呼叫端切片與 Store 共用資料**：正規化會直接修改傳入的 ExtraArgs 底層陣列。現在先深複製設定，失敗交易與呼叫端後續修改都不會改動已保存設定。
- **自動儲存包含未修改欄位**：設定更新 API 的可選欄位改以指標區分「未提供」與明確的 false／空字串；網頁只提交實際修改的欄位，保留原儲存按鈕與既有排程。

### API 相容性

`PUT /api/settings` 仍接受原本完整設定格式，也接受部分更新。未提供或為 null 的可選欄位保留原值；明確的 false 會套用。明確傳入的值仍經過既有正規化與驗證。空的 Hugging Face token 不會隱含清除金鑰，清除仍需 `clear_huggingface_token: true`；公開回應不回傳金鑰內容。

例如只變更配色：

```json
{"ui_theme":"ocean"}
```

### 驗證

修正前，`TestSaveDoesNotShareCallerSlices` 重現儲存會修改呼叫端切片；修正後通過。另新增並通過：

- 32 筆並行 Store 更新全部保留，重新載入的磁碟值與記憶體一致。
- 回呼錯誤、驗證錯誤、寫檔失敗時，原設定與檔案均不改動。
- 24 筆不同收藏與三種不同設定同時儲存，所有變更皆保留。
- 部分更新、明確 false、私密 token 不外洩，以及無效更新整筆拒絕。

上述 Go 測試包含 race detector 檢查。

## 第三輪：複查與邊界驗證

### 問題與修正

- **清理腳本父目錄符號連結**：原本只拒絕目標本身為符號連結；若 `mlx-server` 指向專案外，`.build` 仍可能被刪除。現在比對父目錄實體路徑，拒絕穿過符號連結清理。
- **MLX metadata 整數截斷**：原本 NSNumber 只檢查大於零後取 intValue；0.5 會變成 0，可能造成 head／interval 除以零或低估資源。現在拒絕布林、非整數、非正數及無法表示為 Int 的值，無效資料沿用既有保守預設值。
- 複查前兩輪修改，確認所有設定 API 寫入點已使用交易入口；聊天頁面已載入新串流模組；未更動四人並行生成上限。

### 驗證

清理風險先在臨時目錄內重現，再確認修正後拒絕父目錄連結；另驗證 dist 隱藏檔／巢狀檔清理、保留 dist 目錄、不跟隨子項連結，以及拒絕 dist 本身為連結。測試未對實際專案的 dist 執行清理。

新增更新套件測試，涵蓋合法 ZIP、路徑穿越、絕對路徑、反斜線、符號連結、重複路徑、多個根目錄及使用者資料保留區；僅解壓到臨時目錄，不執行安裝程式。

新增 Swift 測試，確認上下文採用模型與設定的較小有效值、多模態模型優先讀取 text_config、未知 metadata 不虛構能力，以及請求維度只接受正整數。
