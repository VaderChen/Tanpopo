# MLX 通用叢集多模型驗證

2026-10-03（Asia/Taipei）在本機 M4 Pro／64 GiB、macOS 27.0，使用 build 1405 的正式 `rdma8` Runtime 完成測試。**8 份完整模型目錄全部通過單機／雙節點比對，另有 12 組架構與量化微型案例通過。** 所有案例沿用同一個載入前掛鉤與線性層分片核心。

這些結果支持通用方式適用於本機這批完整 safetensors 文字／影像模型。8 份目錄包含同系列的不同來源與權重配置，實際 `model_type` 為 `qwen3`、`qwen3_5`、`gemma4` 三類；不能把它解讀成 8 種不同架構，也不能據此宣稱所有已註冊 checkpoint 都相容。

## 真實權重結果

每個模型使用獨立的 Tanpopo Server 設定與隨機埠，經真實 `lo0` UDP 探索、模型內容校驗、配對與啟動。兩個 Rank 是不同原生程序，共用這台 Mac 的 GPU；這是功能驗證，不是兩台實體 Mac 的效能比較。

| 本機模型 | 載入模式 | 權重檔 GiB | 分片層數 | 每 Rank 線性權重 GiB | 結果 |
| --- | --- | ---: | ---: | ---: | --- |
| Qwen3-0.6B Q4 | 文字 | 0.31 | 196 | 0.12 | 通過 |
| Gemma4-E2B Q4 | 影像 | 3.31 | 390 | 0.63 | 通過 |
| Ornith-1.5-9B Q4 | 文字 | 4.69 | 249 | 2.08 | 通過 |
| Qwen3.5-4B Q4 | 影像 | 2.83 | 346 | 1.24 | 通過 |
| Qwen3.5-4B Q4 aligned | 文字 | 2.83 | 248 | 0.93 | 通過 |
| LM Studio Qwen3.5-4B Q4 | 影像 | 2.83 | 346 | 1.24 | 通過 |
| Qwen3.8-27B Q4 | 影像 | 14.95 | 607 | 7.14 | 通過 |
| Qwen3.8-27B Q4 aligned | 影像 | 14.95 | 607 | 7.14 | 通過 |

名稱採本機模型標示；其中 Qwen3.8 與 Ornith 的實際設定同屬 `qwen3_5`。`aligned` 指本機既有的權重配置版本，不是另一種模型架構。Qwen3.5 aligned 目錄沒有 processor 設定，因此自動使用文字載入器。

固定條件為 temperature 0、Context 4096、Prefill 128、關閉 KV 量化、標準解碼與非 mmap 載入。每份模型都驗證：

- 英文短回覆、多輪中文對話及 688–784 個輸入 Token 的長提示，確認 Prefill 實際跨越多個區塊。
- 5 份影像模型另加入 56 × 56 純紅 PNG，確認圖片處理與生成路徑。
- 單機／雙節點的回答、推理內容、輸入／輸出／總 Token 數及結束原因相同。
- SSE 正常收到 `[DONE]`，重組內容與 Token 數符合單機結果。
- 每輪結束後，兩端 Runtime 停止，叢集 session 清除。

合計 29 組單機／叢集比較、8 次 SSE，共 **66 次生成請求**，全部通過。兩個 27B 版本也完成相同的文字、圖片與串流檢查。

表中的「每 Rank 線性權重」只計算已分片線性層，不含 KV Cache、Embedding、影像前處理、activation、Metal 暫存或特殊算子按需載入的完整權重。Gemma4 的主節點另有約 1.47 GiB 常駐參數；Qwen3.8-27B 約 0.68 GiB。權重檔大小與載入後參數量亦可能不同，不能直接用這些欄位推算整個程序的記憶體峰值。

## 架構與量化微型案例

以 Go 產生固定數值的 safetensors，透過正式 Go Server 與相同的原生 Runtime 執行單機／雙節點。這些小模型用於檢查計算及服務流程，沒有經過語言訓練，不能代替真實大模型驗證。

| 案例 | 驗證的結構 | 結果 |
| --- | --- | --- |
| Llama F32／Q4／Q8，共 3 組 | 一般線性層、U32 packed 量化權重、F32 scales／biases 與未量化 Embedding 混合載入 | 全數通過 |
| Mistral | 註冊表使用 Llama 核心的模型入口 | 通過 |
| Phi3 | 合併 QKV、合併 gate／up 投影 | 通過 |
| Gemma2 | 額外 Norm、tied embedding、logit soft cap | 通過 |
| Starcoder2 | 帶非零偏置的投影與 MLP、LayerNorm | 通過 |
| Qwen2 | 帶偏置的注意力投影 | 通過 |
| Qwen3 | Q／K Norm | 通過 |
| Qwen3 MoE | 一層四專家／top-2 路由搭配一層一般 MLP；專家權重保留在主節點 | 通過 |
| Qwen3.5／Qwen3.5 text，共 2 組 | 巢狀與文字設定格式、循環狀態、深度卷積與完整 Attention 混合 | 全數通過 |

12 組皆通過短／長提示、回答及 Token 數比對、SSE、停止及程序回收。共用測試也通過四人並行與第五人 429、取消隔離、worker／主節點故障、父端 EOF、重啟及啟動失敗回報；底層 collective 另涵蓋 FP32／FP16／BF16 與 Q4 線性層。

多模型工具的 SIGTERM 中斷 Smoke 亦確認以非零狀態退出，回收本次建立的兩個 Server 與 Runtime。

## 結論與驗收界線

目前證據支持繼續使用「依模組結構分片」的共用架構，並以這批真實模型及微型案例作為後續回歸基準。本輪測試沒有發現需要修改 build 1405 分片核心的相容性問題。

- 真實權重樣本皆為 Q4；Q8 與 F32 的完整服務路徑目前由微型案例驗證。
- 真實 MoE 大模型、其他註冊架構、長時間負載、多張／高解析圖片、影片與音訊仍需另外驗證。
- GGUF／Fast GGUF、DFlash、MTP 仍不在此叢集支援範圍；語音、影像生成等其他 Runtime 模型也不列入本次母體。
- 本次使用同一台實體 Mac。先前實體 Wi-Fi 長請求問題與 Thunderbolt RDMA 的驗收狀態不變；不能將同機成功視為網路問題已修復，亦不能保證雙機會加速。
