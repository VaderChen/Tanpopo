## 繁體中文

本版將更新流程整合成「更新並重新啟動」：自動下載與驗證 → 關閉程式 → 安裝更新 → 重新啟動。設定頁會顯示下載進度、安裝狀態與失敗原因。

### 自動更新

- 在「系統設定 → 關於」按「更新並重新啟動」開始。下載期間顯示百分比與位元組數，更新進行中禁止重複操作；瀏覽器斷線後等待服務恢復，再重新載入。
- 僅下載官方最新穩定 Release 中符合目前平台的套件，核對版本、檔案大小及 SHA-256；拒絕同版、降版、draft、prerelease 與來源不符的下載。
- 獨立助手先完成驗證與安裝準備，再讓主程序正常關閉視窗、模型及受管服務。新版完成 HTTP health、PID、隨機 nonce 與版本確認後，才回報更新成功。
- macOS 檢查 App 簽章、相同簽署團隊、Bundle ID 及 Gatekeeper，助手保留完整 App 結構。Linux 先準備 Runtime，再保留設定與安裝目錄內的模型／資料。兩者會備份舊版，並在新版啟動失敗時嘗試還原。
- Windows 透過原生 MSI 安裝，可能出現 UAC 授權。取消或 MSI 失敗時嘗試重啟現有程式；MSI 成功但新版健康檢查失敗時回報失敗，不提供自動降版還原。

### 升級與使用條件

**舊版需先安裝本版，後續才可使用一鍵自動更新。** 啟動時及每小時的版本檢查只會通知，按下更新按鈕才會開始安裝。原始碼工作區與不完整的發行目錄停用自動更新。

本機 loopback 介面可在免登入模式更新；遠端操作必須啟用管理登入並登入。macOS／Linux 需要安裝目錄旁的寫入權限，以及下載、新版、備份和 Linux 內部資料複製所需空間；Linux 的系統相依套件與 GPU 權限仍須先備妥。未勾選「記住我」的管理工作階段可能需要重新登入；TCP Ring 重啟後需重新選取與配對節點。

README 與安裝包已補充上述條件。完整流程、API、日誌、資料保留與復原限制見 [自動更新指南](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-0108/docs/APP-UPDATE.md)。本次不變更 MLX Runtime 與 RDMA 支援範圍。

### 驗證範圍

- Go 更新器／API／主程序的 race 測試、前端語法與 Smoke 通過，涵蓋下載中斷、摘要不符、來源限制、重複更新、進度、斷線等待與完成後重載。
- 隔離目錄與真正子程序驗證安裝切換、HTTP health／PID／nonce／版本確認，以及新版失敗後還原並重新啟動舊版。
- macOS 正式 DMG 完成簽章、Apple 公證及 Gatekeeper 檢查；另驗證實際掛載、在外接磁碟準備 App，以及完整簽章助手啟動。三平台主程式完成建置。

上述測試不會替換使用者的實際安裝。Windows MSI／UAC 與 Linux ZIP 完整安裝仍待對應作業系統實機驗證；不把交叉編譯視為安裝驗收。

## English

This release adds **Update and restart**: download and verify → close the app → install → relaunch. The settings page shows download progress, installation status, and failure details.

### Automatic updates

- Choose **System settings → About → Update and restart**. The page displays download percentage and byte counts, prevents duplicate requests, waits through the browser's temporary disconnection, and reloads when the service returns.
- Only the matching platform package from the official latest stable Release is accepted. Version, size, and SHA-256 checks reject the current version, downgrades, drafts, prereleases, and untrusted download sources.
- A separate helper verifies and prepares the package before the main process closes its window, models, and managed services normally. Success requires the new process to confirm HTTP health, PID, a random nonce, and its version.
- macOS checks the App signature, matching signing team, Bundle ID, and Gatekeeper; the helper retains the complete App bundle. Linux prepares the Runtime before preserving configuration and model/data paths inside the installation. Both platforms back up the old installation and attempt rollback if the new process fails startup checks.
- Windows uses the native MSI installer and may request UAC approval. Cancellation or MSI failure attempts to relaunch the existing app. If MSI succeeds but the new app fails health checks, the update reports failure without automatic downgrade rollback.

### Upgrade and operating requirements

**Install this release once before using automatic updates from an older version.** Startup and hourly checks only notify you; installation starts when you press the update button. Source checkouts and incomplete package layouts cannot update themselves.

Local loopback access can update without administrator sign-in. Remote updates require administrator authentication to be enabled and an authenticated session. macOS/Linux need write access beside the installation and space for the download, new files, backups, and Linux internal data copies. Prepare Linux system dependencies and GPU permissions first. Sessions without **Remember me** may require sign-in again; TCP Ring nodes must be selected and paired again after restarting.

The READMEs and packages now document these requirements. See the [automatic update guide (Traditional Chinese)](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-0108/docs/APP-UPDATE.md) for the workflow, APIs, logs, data preservation, and recovery limits. This release does not change the MLX Runtime or RDMA support scope.

### Verification scope

- Go updater/API/main-process race tests and frontend syntax/Smoke checks passed, including interrupted downloads, digest mismatches, source restrictions, duplicate updates, progress, disconnection handling, and reload after completion.
- Isolated directories and real child processes verified installation swaps, HTTP health/PID/nonce/version checks, and restoration and relaunch of the old version after a failed new launch.
- The macOS DMG passed signature, Apple notarization, and Gatekeeper checks. Additional tests exercised real mounting, App preparation on an external volume, and launch of a complete signed helper bundle. Main binaries were built for all three platforms.

These tests do not replace the user's actual installation. Windows MSI/UAC and complete Linux ZIP installation still need testing on their respective operating systems; cross-compilation is not installation validation.

- `Tanpopo-1.26.1003-build-0108-x64.msi`: Windows x64.
- `Tanpopo-1.26.1003-build-0108-linux-x64.zip`: Linux x64; builds the Vulkan Runtime from bundled sources on first run.
- `Tanpopo-1.26.1003-build-0108-SHA256SUMS.txt`: SHA-256 checksums for all three packages.

## 日本語

本版では「更新して再起動」を追加しました。自動ダウンロードと検証 → アプリ終了 → インストール → 再起動の順に処理し、設定画面にダウンロードの進行状況、インストール状態、失敗理由を表示します。

### 自動更新

- **システム設定 → このアプリについて → 更新して再起動**から開始します。ダウンロードの割合とバイト数を表示し、重複操作を防ぎます。ブラウザーの接続が一時的に切れた場合はサービス復帰を待って再読み込みします。
- 公式の最新安定版 Release から、使用中のプラットフォームに一致するパッケージのみ取得します。版、サイズ、SHA-256 を照合し、同版、旧版、draft、prerelease、不正な配布元を拒否します。
- 独立したヘルパーが検証と準備を終えた後、主プロセスがウィンドウ、モデル、管理対象サービスを正常終了します。新版の HTTP health、PID、ランダム nonce、版を確認して初めて成功と判定します。
- macOS は App の署名、署名チームの一致、Bundle ID、Gatekeeper を検証し、ヘルパーも完全な App 構造を保持します。Linux は Runtime を先に準備し、設定とインストール先内部のモデル／データを保持します。両 OS とも旧版をバックアップし、新版の起動失敗時に復元を試みます。
- Windows は標準 MSI を使用し、UAC の承認が必要な場合があります。キャンセルや MSI 失敗時は既存アプリの再起動を試みます。MSI 成功後に新版の health 検査が失敗した場合はエラーを報告し、自動的な旧版への復元は行いません。

### アップグレードと利用条件

**旧版からは最初に本版をインストールしてください。その後の更新で自動更新を利用できます。** 起動時と毎時の確認は通知のみで、更新ボタンを押すとインストールを開始します。ソースの作業ディレクトリや不完全な配布構成では自動更新を無効にします。

ローカル loopback では管理者ログインなしでも更新できます。リモート操作には管理者認証を有効にし、ログインする必要があります。macOS/Linux ではインストール先の親ディレクトリへの書き込み権限と、ダウンロード、新版、バックアップ、Linux 内部データのコピー用容量が必要です。Linux のシステム依存パッケージと GPU 権限は事前に準備してください。「ログイン状態を保持」を選んでいない場合は再ログインが必要になることがあります。TCP Ring は再起動後にノードを再選択してペアリングしてください。

README と配布文書にも条件を追記しました。手順、API、ログ、データ保持、復元の制限は [自動更新ガイド（繁体字中国語）](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-0108/docs/APP-UPDATE.md) を参照してください。MLX Runtime と RDMA の対応範囲は変更していません。

### 検証範囲

- Go 更新器/API/主プロセスの race テストと、フロントエンドの構文・Smoke 検査に合格しました。ダウンロード中断、摘要の不一致、配布元制限、重複更新、進行状況、切断待機、完了後の再読み込みを確認しました。
- 隔離ディレクトリと実際の子プロセスで、インストール切り替え、HTTP health/PID/nonce/版の確認、新版起動失敗時の旧版復元と再起動を検証しました。
- macOS DMG は署名、Apple 公証、Gatekeeper 検査を通過しました。実際のマウント、外付けディスクでの App 準備、完全な署名付きヘルパーの起動も検証し、3 プラットフォームの主プログラムをビルドしました。

検証はユーザーの実際のインストールを置き換えません。Windows MSI/UAC と Linux ZIP の全インストール工程は、各 OS の実機検証が必要です。クロスコンパイルをインストール検証とは扱いません。

## 한국어

이번 버전에는 **업데이트 후 재시작**이 추가되었습니다. 자동 다운로드 및 검증 → 앱 종료 → 설치 → 다시 시작 순서로 진행하며 설정 화면에 다운로드 진행률, 설치 상태, 실패 이유를 표시합니다.

### 자동 업데이트

- **시스템 설정 → 정보 → 업데이트 후 재시작**에서 시작합니다. 다운로드 백분율과 바이트 수를 표시하고 중복 실행을 막습니다. 브라우저 연결이 일시적으로 끊기면 서비스 복구를 기다린 뒤 페이지를 다시 불러옵니다.
- 공식 최신 안정 Release에서 현재 플랫폼과 일치하는 패키지만 받습니다. 버전, 크기, SHA-256을 확인하며 동일 버전, 다운그레이드, draft, prerelease, 신뢰할 수 없는 다운로드 출처를 거부합니다.
- 별도 도우미가 검증과 준비를 마친 후 주 프로세스가 창, 모델, 관리 중인 서비스를 정상 종료합니다. 새 프로세스의 HTTP health, PID, 무작위 nonce, 버전을 확인한 뒤에만 성공을 보고합니다.
- macOS는 App 서명, 동일한 서명 팀, Bundle ID, Gatekeeper를 확인하며 도우미도 완전한 App 구조를 유지합니다. Linux는 Runtime을 먼저 준비하고 설정과 설치 폴더 내부의 모델/데이터를 보존합니다. 두 OS 모두 이전 버전을 백업하며 새 버전의 시작 검사가 실패하면 복원을 시도합니다.
- Windows는 기본 MSI 설치 프로그램을 사용하며 UAC 승인이 필요할 수 있습니다. 취소 또는 MSI 실패 시 기존 앱의 재시작을 시도합니다. MSI 설치는 성공했지만 새 앱의 health 검사가 실패하면 오류를 보고하며 자동 다운그레이드 복원은 제공하지 않습니다.

### 업그레이드 및 사용 조건

**이전 버전에서는 먼저 이번 버전을 설치해야 이후 업데이트에 자동 업데이트를 사용할 수 있습니다.** 시작 시와 매시간 수행하는 버전 확인은 알림만 표시하며 업데이트 버튼을 눌러야 설치를 시작합니다. 소스 작업 공간과 불완전한 배포 폴더에서는 자동 업데이트를 비활성화합니다.

로컬 loopback에서는 관리자 로그인 없이 업데이트할 수 있습니다. 원격 업데이트는 관리자 인증을 켜고 로그인해야 합니다. macOS/Linux에는 설치 폴더 옆의 쓰기 권한과 다운로드, 새 파일, 백업, Linux 내부 데이터 복사 공간이 필요합니다. Linux 시스템 의존 패키지와 GPU 권한은 먼저 준비하세요. 로그인 유지 옵션을 선택하지 않은 세션은 다시 로그인해야 할 수 있으며 TCP Ring은 다시 시작한 뒤 노드를 다시 선택하고 페어링해야 합니다.

README와 배포 문서에 이러한 조건을 추가했습니다. 절차, API, 로그, 데이터 보존, 복원 제한은 [자동 업데이트 가이드(중국어 번체)](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-0108/docs/APP-UPDATE.md)를 참고하세요. MLX Runtime과 RDMA 지원 범위는 변경하지 않았습니다.

### 검증 범위

- Go 업데이트 도구/API/주 프로세스의 race 테스트와 프런트엔드 구문/Smoke 검사를 통과했습니다. 다운로드 중단, 해시 불일치, 출처 제한, 중복 업데이트, 진행률, 연결 복구 대기, 완료 후 다시 불러오기를 확인했습니다.
- 격리된 폴더와 실제 자식 프로세스로 설치 교체, HTTP health/PID/nonce/버전 검사, 새 버전 시작 실패 후 이전 버전 복원 및 재시작을 검증했습니다.
- macOS DMG는 서명, Apple 공증, Gatekeeper 검사를 통과했습니다. 실제 마운트, 외장 디스크에서의 App 준비, 완전한 서명된 도우미 실행을 추가로 검증했으며 세 플랫폼의 주 프로그램을 빌드했습니다.

이 테스트는 사용자의 실제 설치를 교체하지 않습니다. Windows MSI/UAC와 Linux ZIP의 전체 설치 과정은 해당 OS에서 실제 검증이 필요합니다. 크로스 컴파일을 설치 검증으로 간주하지 않습니다.
