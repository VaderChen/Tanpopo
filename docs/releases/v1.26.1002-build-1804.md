## 繁體中文

本版加入原生 MLX 分散推論，以及可在區網搜尋、複選並啟用節點的 TCP Ring 介面。更新 README 動態展示、操作指南與發行包內的文件及授權檔案。

### TCP Ring 與 RDMA

- Apple Silicon 的 TCP Ring 支援 2–8 個節點。各台按「搜尋節點」開啟探索；主節點在清單勾選 1–7 個遠端 Server，再按「配對並啟用」。本機自動加入，不需配對金鑰、SSH 或 Python。
- 重新整理叢集卡片：搜尋按鈕位於主要操作區，網路設定預設收合；節點清單顯示可用、忙碌與版本不符狀態，支援逐台勾選及全選可用節點，並顯示交握進度與錯誤。
- 所有成員完成準備後才啟動；核對 Runtime、模型內容 SHA-256 與分片計畫。任一節點失敗會整組回滾，任一端停止會清理整組；另有租約與父程序 EOF 回收。
- 線性層採通用輸出列分片，支援不能整除的三節點組合。Rank 0 保留 Attention、KV Cache、抽樣與四個生成名額，其餘 Rank 執行線性層分片。
- 支援 safetensors 格式的 Llama/Mistral、Qwen2、Qwen3 文字模型。不支援 GGUF／Fast GGUF、多模態、MoE、DFlash、MTP；不支援的組合直接回報錯誤，不退回單機。
- 原生 JACCL RDMA 路徑仍為雙節點，需依指南準備 Thunderbolt 設備、系統與 SDK。TCP Ring 不會自動改用 RDMA。

### 升級與使用條件

所有節點需一起更新 Tanpopo Server 與**同一份** MLX Runtime。本版 Runtime 為 `1.5.0-mlxswiftlm-3.31.4-gguf-dflash2-mtp-mmap-fastgguf-cache12-rdma4`；探索協定 v2 不與舊版共享金鑰協定互通。各台需準備相同模型內容及相同模型相對路徑。重新啟動會恢復探索，但需重新選取與配對叢集。

免金鑰模式限可信任區網。探索、控制與張量通道未加密，來源 IP 與 nonce 不提供密碼學身分驗證。各台必須允許 UDP multicast、管理 HTTP 埠及 Ring TCP 連線；管理登入與模型 API 存取控制仍維持原本設定。

詳細步驟、API、網路條件與測試指令見 [MLX 分散推論與 RDMA 使用指南](https://github.com/VaderChen/Tanpopo/blob/v1.26.1002-build-1804/docs/MLX-RDMA.md)。

## English

This release adds native MLX distributed inference and a TCP Ring interface for discovering, selecting, and starting multiple Servers on a LAN. It also updates the README demo, operating guide, and documentation and license files included in the packages.

### TCP Ring and RDMA

- TCP Ring supports 2–8 Apple Silicon nodes. Enable discovery on each Server with **Search nodes** (`搜尋節點`), select 1–7 remote Servers on the coordinator, then choose **Pair and start** (`配對並啟用`). The local Mac joins automatically; no pairing key, SSH, or Python is required.
- The redesigned cluster card places search in the main action area and keeps network settings collapsed by default. The dialog shows available, busy, and incompatible nodes, supports individual selection or selecting all available nodes, and displays handshake progress and errors.
- All members must finish preparation before startup. The system checks the Runtime, model-content SHA-256, and sharding plan. A startup failure rolls back the entire group; stopping any member stops the group. Leases and parent-process EOF detection also reclaim abandoned processes.
- Linear layers use general output-row sharding, including uneven three-node partitions. Rank 0 retains Attention, KV Cache, sampling, and four generation slots; the other ranks compute their linear-layer shards.
- Supported text models are Llama/Mistral, Qwen2, and Qwen3 in safetensors format. GGUF/Fast GGUF, multimodal models, MoE, DFlash, and MTP are unsupported. Unsupported combinations return an error without falling back to single-node execution.
- Native JACCL RDMA remains limited to two nodes and requires the Thunderbolt hardware, operating system, and SDK described in the guide. TCP Ring does not automatically switch to RDMA.

### Upgrade and operating requirements

Update Tanpopo Server and deploy **the same MLX Runtime artifact** on every node together. This release uses `1.5.0-mlxswiftlm-3.31.4-gguf-dflash2-mtp-mmap-fastgguf-cache12-rdma4`. Discovery protocol v2 is incompatible with the earlier shared-key protocol. All nodes need identical model contents and matching relative model paths. Restarting restores discovery, but the cluster must be selected and paired again.

Keyless mode is intended for trusted LANs only. Discovery, control, and tensor channels are unencrypted; source IP addresses and nonces do not provide cryptographic peer authentication. Allow UDP multicast, the management HTTP port, and Ring TCP connections between nodes. Administrator sign-in and model API access controls retain their configured policies.

See the [MLX distributed inference and RDMA guide (Traditional Chinese)](https://github.com/VaderChen/Tanpopo/blob/v1.26.1002-build-1804/docs/MLX-RDMA.md) for setup, APIs, networking requirements, and test commands.

### Documentation and demo

- Traditional Chinese, English, Japanese, and Korean READMEs now show the updated GIF: model selection, discovery and multi-selection, pairing and startup, and streaming chat.
- The GIF operates the actual project UI and continuously displays a DEMO label. Nodes, models, utilization readings, and responses are simulated data; they are not evidence of loading speed or inference performance.
- Documentation now covers the distributed inference contract, troubleshooting, protocol upgrades, and the remaining hardware validation work.
- Packages include the images and documentation referenced by the READMEs, the current Tanpopo Source Available License v1.1, commercial licensing information, and third-party notices.

### Verification and limitations

- Go cluster/API/Runtime race tests, native Swift configuration tests, frontend Smoke tests, and syntax checks passed.
- Two-node inference with tiny Llama, Qwen2, and Qwen3 fixtures on one machine verified matching single/two-node outputs, four concurrent requests, HTTP 429 for a fifth request, cancellation isolation, SSE, and failure cleanup.
- Three independent Go Servers and three Swift Runtimes used real UDP discovery and production management APIs to verify keyless handshakes, multi-selection, matching single/three-node outputs, SSE, model-mismatch rollback, and whole-group shutdown.
- Native three-rank Smoke tests covered FP32/FP16/BF16, ordinary and Q4 linear layers, uneven shards, and collective operations interleaved across four callers.

These tests used one Apple Silicon Mac and tiny model fixtures. Networking and firewalls across physical Macs, large-model capacity/performance, and Thunderbolt RDMA **still require hardware testing**. Two machines are not guaranteed to improve throughput. Windows/Linux packages provide the cross-platform management service and llama.cpp path; MLX distributed inference is Apple Silicon only.

## 日本語

本リリースでは、ネイティブ MLX 分散推論と、LAN 上の Server を検索・複数選択して起動できる TCP Ring 画面を追加しました。README のデモ、操作ガイド、配布パッケージ内の文書とライセンスファイルも更新しました。

### TCP Ring と RDMA

- Apple Silicon の TCP Ring は 2～8 ノードに対応します。各 Server で「搜尋節點」（ノードを検索）を押して探索を有効にし、コーディネーターで 1～7 台のリモート Server を選択して「配對並啟用」（ペアリングして起動）を押します。ローカル Mac は自動的に参加し、ペアリングキー、SSH、Python は不要です。
- クラスターカードを整理し、検索ボタンを主要操作エリアに配置しました。ネットワーク設定は初期状態で折りたたまれます。一覧には接続可能・使用中・非互換の状態を表示し、個別選択と接続可能ノードの一括選択、ハンドシェイクの進行状況とエラー表示に対応します。
- 全メンバーの準備完了後に起動し、Runtime、モデル内容の SHA-256、分割計画を照合します。起動に失敗するとグループ全体をロールバックし、どのメンバーから停止しても全体を終了します。リースと親プロセスの EOF 検知でも残存プロセスを回収します。
- 線形層は汎用的な出力行の分割方式を使用し、3 ノードなどで行数を均等に分割できない場合にも対応します。Rank 0 は Attention、KV Cache、サンプリング、4 つの生成枠を担当し、他の Rank が線形層の分割部分を計算します。
- 対応するテキストモデルは safetensors 形式の Llama/Mistral、Qwen2、Qwen3 です。GGUF/Fast GGUF、マルチモーダル、MoE、DFlash、MTP は非対応です。非対応の組み合わせはエラーを返し、単一ノード実行へ自動的に切り替えません。
- ネイティブ JACCL RDMA は引き続き 2 ノード構成です。ガイドに記載された Thunderbolt 機器、OS、SDK が必要です。TCP Ring が RDMA に自動的に切り替わることはありません。

### アップグレードと利用条件

全ノードの Tanpopo Server をまとめて更新し、**同一の MLX Runtime 配布物**を配置してください。本版の Runtime は `1.5.0-mlxswiftlm-3.31.4-gguf-dflash2-mtp-mmap-fastgguf-cache12-rdma4` です。探索プロトコル v2 は従来の共有キー方式と互換性がありません。全ノードでモデルの内容とモデルの相対パスを一致させる必要があります。再起動で探索は復元されますが、クラスターの選択とペアリングはやり直してください。

キー不要モードは信頼できる LAN 専用です。探索・制御・テンソル通信は暗号化されておらず、送信元 IP と nonce は暗号学的な相手認証を提供しません。ノード間で UDP multicast、管理 HTTP ポート、Ring TCP 接続を許可してください。管理者ログインとモデル API のアクセス制御には、設定済みのポリシーが引き続き適用されます。

設定手順、API、ネットワーク条件、テストコマンドは [MLX 分散推論と RDMA ガイド（繁体字中国語）](https://github.com/VaderChen/Tanpopo/blob/v1.26.1002-build-1804/docs/MLX-RDMA.md) を参照してください。

### 検証と制限事項

- Go のクラスター/API/Runtime の race テスト、ネイティブ Swift の設定テスト、フロントエンドの Smoke テスト、構文チェックに合格しました。
- 1 台の Mac 上で微小な Llama・Qwen2・Qwen3 のテストモデルを使い、単一/2 ノードの出力一致、4 リクエスト同時実行、5 件目への HTTP 429、キャンセルの分離、SSE、障害時の回収を検証しました。

これらは 1 台の Apple Silicon Mac と微小なテストモデルによる検証です。物理的に異なる Mac 間のネットワークとファイアウォール、大型モデルの容量・性能、Thunderbolt RDMA は、**実機での検証が必要です**。2 台構成による高速化は保証しません。Windows/Linux パッケージにはクロスプラットフォームの管理サービスと llama.cpp 実行経路を含みますが、MLX 分散推論は Apple Silicon 専用です。

## 한국어

이번 릴리스에는 네이티브 MLX 분산 추론과 LAN에서 Server를 검색하고 여러 노드를 선택해 시작하는 TCP Ring 화면이 추가되었습니다. README 데모, 사용 가이드, 배포 패키지에 포함된 문서와 라이선스 파일도 업데이트했습니다.

### TCP Ring 및 RDMA

- Apple Silicon의 TCP Ring은 2–8개 노드를 지원합니다. 각 Server에서 ‘搜尋節點’(노드 검색)을 눌러 탐색을 켜고, 코디네이터에서 원격 Server 1–7대를 선택한 뒤 ‘配對並啟用’(페어링 후 시작)을 누릅니다. 로컬 Mac은 자동으로 참여하며 페어링 키, SSH, Python이 필요하지 않습니다.
- 클러스터 카드를 정리해 검색 버튼을 주요 작업 영역에 배치하고 네트워크 설정은 기본적으로 접었습니다. 목록에는 연결 가능, 사용 중, 호환되지 않음 상태가 표시됩니다. 개별 선택과 사용 가능한 노드 전체 선택을 지원하며 핸드셰이크 진행 상황과 오류를 보여 줍니다.
- 모든 구성원의 준비가 완료된 후 시작하며 Runtime, 모델 내용의 SHA-256, 분할 계획을 확인합니다. 시작에 실패하면 그룹 전체를 롤백하고, 어느 구성원에서 중지해도 전체 그룹을 종료합니다. 임대 만료와 부모 프로세스의 EOF 감지도 남은 프로세스를 정리합니다.
- 선형 계층은 범용 출력 행 분할 방식을 사용하며 3개 노드처럼 행 수가 균등하게 나뉘지 않는 구성도 지원합니다. Rank 0은 Attention, KV Cache, 샘플링, 4개의 생성 슬롯을 담당하고 나머지 Rank는 선형 계층의 분할된 부분을 계산합니다.
- 지원하는 텍스트 모델은 safetensors 형식의 Llama/Mistral, Qwen2, Qwen3입니다. GGUF/Fast GGUF, 멀티모달, MoE, DFlash, MTP는 지원하지 않습니다. 지원하지 않는 조합은 오류를 반환하며 단일 노드 실행으로 자동 전환하지 않습니다.
- 네이티브 JACCL RDMA는 계속 2개 노드로 제한됩니다. 가이드에 명시된 Thunderbolt 장비, 운영 체제, SDK가 필요합니다. TCP Ring이 RDMA로 자동 전환되지는 않습니다.

### 업그레이드 및 사용 조건

모든 노드의 Tanpopo Server를 함께 업데이트하고 **동일한 MLX Runtime 배포 파일**을 사용해야 합니다. 이번 버전의 Runtime은 `1.5.0-mlxswiftlm-3.31.4-gguf-dflash2-mtp-mmap-fastgguf-cache12-rdma4`입니다. 탐색 프로토콜 v2는 이전 공유 키 프로토콜과 호환되지 않습니다. 모든 노드의 모델 내용과 모델 상대 경로가 같아야 합니다. 다시 시작하면 탐색은 복원되지만 클러스터를 다시 선택하고 페어링해야 합니다.

키 없는 모드는 신뢰할 수 있는 LAN에서만 사용해야 합니다. 탐색, 제어, 텐서 통신은 암호화되지 않으며, 출발지 IP와 nonce는 암호학적 상대 인증을 제공하지 않습니다. 노드 간 UDP multicast, 관리 HTTP 포트, Ring TCP 연결을 허용해야 합니다. 관리자 로그인과 모델 API 접근 제어에는 기존에 설정한 정책이 계속 적용됩니다.

설정 절차, API, 네트워크 조건, 테스트 명령은 [MLX 분산 추론 및 RDMA 가이드(중국어 번체)](https://github.com/VaderChen/Tanpopo/blob/v1.26.1002-build-1804/docs/MLX-RDMA.md)를 참고하세요.

### 검증 및 제한 사항

- Go 클러스터/API/Runtime의 race 테스트, 네이티브 Swift 설정 테스트, 프런트엔드 Smoke 테스트, 구문 검사를 통과했습니다.
- 한 대의 Mac에서 소형 Llama, Qwen2, Qwen3 테스트 모델로 단일/2개 노드의 출력 일치, 요청 4개 동시 처리, 다섯 번째 요청의 HTTP 429, 취소 격리, SSE, 장애 시 정리를 검증했습니다.
- 독립된 Go Server 3개와 Swift Runtime 3개를 실행하고 실제 UDP 탐색과 정식 관리 API로 키 없는 핸드셰이크, 다중 선택, 단일/3개 노드의 출력 일치, SSE, 모델 불일치 시 롤백, 전체 그룹 중지를 검증했습니다.
- 네이티브 3 Rank Smoke 테스트는 FP32/FP16/BF16, 일반/Q4 선형 계층, 불균등 분할, 4개 호출자의 요청이 교차하는 collective 연산을 검증했습니다.

이 테스트는 Apple Silicon Mac 한 대와 소형 테스트 모델을 사용했습니다. 서로 다른 실제 Mac 간 네트워크와 방화벽, 대형 모델의 수용량·성능, Thunderbolt RDMA는 **실제 장비 테스트가 필요합니다**. 두 대를 사용한다고 처리 속도가 반드시 향상되는 것은 아닙니다. Windows/Linux 패키지는 크로스 플랫폼 관리 서비스와 llama.cpp 실행 경로를 제공하며, MLX 분산 추론은 Apple Silicon 전용입니다.
