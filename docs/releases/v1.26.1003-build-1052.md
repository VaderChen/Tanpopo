## 繁體中文

本版讓 TCP Ring 依模型結構選擇可分片的線性層，加入 Qwen3.5 的文字分散推論，並修正多個 Server 同時啟動時可能卡在連線的問題。

### 變更

- 模型相容性改由原生 MLX Runtime 回報。可直接讀取權重列的標準 Linear／QuantizedLinear 層分散計算；自訂層、轉換過的權重、MoE 專用運算、注意力、循環狀態及 KV cache 留在主節點。直接存取完整權重的運算保留原始行為，不逐一依模型名稱加入特例。
- Qwen3.5 含有視覺設定的模型可用文字載入路徑執行 TCP Ring。雙機模式仍不接受圖片、GGUF、DFlash 或 MTP；相容性清單不代表每一個模型都已實機驗證，也不保證效能提升。
- 啟動流程增加所有節點完成準備的屏障，先釋放預約通訊埠，再啟動原生 Runtime，避免 worker 誤連上暫時的通訊埠預約服務。
- 搜尋列表允許先勾選忙碌但相容的節點，並在重新整理後保留選取；開始前會列出需停止服務的節點及模型限制，讓按鈕停用原因更清楚。

### 升級條件

**所有參與節點都必須更新完整 Tanpopo App／Server 與 MLX Runtime。** 本版 Runtime 為 `1.5.0-mlxswiftlm-3.31.4-gguf-dflash2-mtp-mmap-fastgguf-cache12-rdma5`，無法與舊版 `rdma4` 混用。所有節點須使用相同發行包的 Runtime 及相同模型檔案；只比對版本名稱不足以通過交握。

已安裝 build 0108 的使用者可按「更新並重新啟動」。只有模型 API IP 白名單時，請在各台 Mac 的 Tanpopo 視窗或 loopback 管理頁面操作；從其他電腦更新仍須啟用管理登入並登入。更新後重新搜尋、選取與配對節點。詳見 [自動更新指南](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1052/docs/APP-UPDATE.md) 與 [分散推論說明](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1052/docs/MLX-RDMA.md)。

### 驗證範圍

- Go 叢集／Runtime 管理／API 與前端 Smoke 通過；三個獨立 Server 的探索、準備、啟動與停止通過。
- 原生三節點 collective、Llama／Qwen2／Qwen3／Qwen3.5／Qwen3.5Text 小型模型、長提示詞、串流、併發上限、取消與重新啟動 Smoke 通過。
- 真實 Qwen3.5-4B 以同一台 Mac 上的兩個獨立 Server 驗證：248 個線性層分片；英文與中文提示的結果和 token 數均與單機一致，串流及停止清理通過。
- 跨兩台 Mac 的 Qwen3-0.6B TCP Ring 已在先前 `rdma4` 完成；本版 Qwen3.5 跨兩台 Mac、Thunderbolt RDMA／JACCL 仍待實機驗證。單機模擬不代表這些項目已通過。
- macOS DMG 完成簽章、Apple 公證、Gatekeeper 與隔離更新 Smoke；三平台主程式完成建置。Windows MSI／UAC 與 Linux ZIP 完整安裝仍待各平台驗證。

## English

TCP Ring now chooses shardable linear layers from the model structure, adds distributed text inference for Qwen3.5, and fixes a connection hang when multiple Servers start together.

### Changes

- The native MLX Runtime reports model compatibility. Standard Linear/QuantizedLinear layers whose weight rows can be read directly are distributed. Custom layers, transformed weights, specialized MoE operations, attention, recurrent state, and KV caches stay on the coordinator. Operations that access full weights retain their original behavior without adding individual model-name exceptions.
- Qwen3.5 checkpoints containing vision configuration can use the text loader for TCP Ring. Distributed mode still excludes image input, GGUF, DFlash, and MTP. The compatibility list does not mean every model has been tested on hardware or promise faster inference.
- A preparation barrier across all nodes releases reserved ports before native Runtimes start, preventing workers from connecting to temporary port reservations.
- Discovery allows selecting busy but compatible nodes and preserves selection after refresh. Before starting, the dialog names nodes whose services must stop and explains model restrictions so disabled buttons have a clear reason.

### Upgrade requirements

**Update the complete Tanpopo App/Server and MLX Runtime on every participating node.** This release uses `1.5.0-mlxswiftlm-3.31.4-gguf-dflash2-mtp-mmap-fastgguf-cache12-rdma5` and cannot mix with `rdma4`. All nodes need the Runtime from the same release package and identical model files; matching version labels alone is insufficient for the handshake.

Users on build 0108 can choose **Update and restart**. If only the model API IP allowlist is enabled, update from the Tanpopo window or loopback management page on each Mac. Updating from another computer still requires enabled administrator authentication and a signed-in session. Discover, select, and pair nodes again after updating. See the [automatic update guide](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1052/docs/APP-UPDATE.md) and [distributed inference guide](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1052/docs/MLX-RDMA.md) in Traditional Chinese.

### Verification scope

- Go cluster/Runtime management/API and frontend Smoke checks passed, including discovery, preparation, startup, and shutdown across three independent Servers.
- Native three-rank collectives; small Llama/Qwen2/Qwen3/Qwen3.5/Qwen3.5Text models; long prompts; streaming; concurrency limits; cancellation; and restart Smoke checks passed.
- A real Qwen3.5-4B model ran through two independent Servers on one Mac with 248 sharded linear layers. English and Chinese results and token counts matched single-node inference; streaming and shutdown cleanup passed.
- Qwen3-0.6B TCP Ring previously passed across two physical Macs with `rdma4`. Qwen3.5 across two physical Macs on this release and Thunderbolt RDMA/JACCL still await hardware validation. Single-Mac simulation does not validate those paths.
- The macOS DMG passed signing, Apple notarization, Gatekeeper, and isolated update Smoke checks. Main binaries were built for all three platforms; full Windows MSI/UAC and Linux ZIP installation still require validation on those platforms.

### Downloads

- `Tanpopo-1.26.1003-build-1052-arm64.dmg`: macOS Apple Silicon.
- `Tanpopo-1.26.1003-build-1052-x64.msi`: Windows x64.
- `Tanpopo-1.26.1003-build-1052-linux-x64.zip`: Linux x64; builds the Vulkan Runtime from bundled sources on first run.
- `Tanpopo-1.26.1003-build-1052-SHA256SUMS.txt`: SHA-256 checksums for all three packages.

## 日本語

TCP Ring がモデル構造から分割可能な線形層を選択するようになり、Qwen3.5 のテキスト分散推論を追加しました。複数の Server を同時に起動すると接続待ちで停止する問題も修正しました。

### 変更内容

- 対応モデルはネイティブ MLX Runtime が報告します。重みの行を直接読み取れる標準 Linear/QuantizedLinear 層を分散計算し、独自層、変換済み重み、MoE 専用演算、attention、循環状態、KV cache は主ノードに保持します。完全な重みに直接アクセスする演算は元の動作を維持し、モデル名ごとの例外を追加しません。
- 視覚設定を含む Qwen3.5 も、テキスト用ローダーで TCP Ring を利用できます。分散モードでは画像入力、GGUF、DFlash、MTP は引き続き対象外です。対応一覧は全モデルの実機検証や高速化を保証するものではありません。
- 全ノードの準備完了を待ち、予約ポートを解放してからネイティブ Runtime を起動します。worker が一時的なポート予約サービスに接続してしまう問題を防ぎます。
- 使用中でも互換性のあるノードは検索一覧で選択でき、更新後も選択を保持します。開始前に停止が必要なノードとモデル制限を表示し、ボタンが無効な理由を明確にします。

### アップグレード条件

**参加する全ノードで Tanpopo App/Server と MLX Runtime を含む完全な更新が必要です。** 本版の Runtime は `1.5.0-mlxswiftlm-3.31.4-gguf-dflash2-mtp-mmap-fastgguf-cache12-rdma5` で、旧 `rdma4` と混在できません。同一配布パッケージの Runtime と同一のモデルファイルが必要です。版の名前が一致するだけではハンドシェイクを通過しません。

build 0108 では「更新して再起動」を利用できます。モデル API の IP 許可リストだけを有効にしている場合は、各 Mac の Tanpopo ウィンドウまたは loopback 管理ページから更新してください。他のコンピューターから更新する場合は、管理者認証の有効化とログインが必要です。更新後に再検索し、ノードを選択してペアリングしてください。詳しくは [自動更新ガイド](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1052/docs/APP-UPDATE.md) と [分散推論ガイド](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1052/docs/MLX-RDMA.md)（繁体字中国語）を参照してください。

### 検証範囲

- Go のクラスタ/Runtime 管理/API とフロントエンドの Smoke 検査に合格しました。3 つの独立 Server の探索、準備、起動、停止を確認しました。
- ネイティブ 3 rank collective、小型 Llama/Qwen2/Qwen3/Qwen3.5/Qwen3.5Text、長いプロンプト、ストリーミング、同時実行制限、キャンセル、再起動の Smoke 検査に合格しました。
- 実際の Qwen3.5-4B を同じ Mac 上の 2 つの独立 Server で実行し、248 の線形層を分割しました。英語と中国語の応答および token 数が単機推論と一致し、ストリーミングと停止時の後処理も確認しました。
- Qwen3-0.6B は先行する `rdma4` で 2 台の実機 Mac 間の TCP Ring 検証を完了しています。本版での Qwen3.5 の 2 台実機検証と Thunderbolt RDMA/JACCL は未検証です。1 台での模擬実行をこれらの検証とは扱いません。
- macOS DMG は署名、Apple 公証、Gatekeeper、隔離更新 Smoke を通過しました。3 プラットフォームの主プログラムをビルドしましたが、Windows MSI/UAC と Linux ZIP の全インストール工程は各 OS での検証が必要です。

## 한국어

TCP Ring이 모델 구조에서 분할 가능한 선형 계층을 선택하도록 바뀌었으며 Qwen3.5 텍스트 분산 추론을 추가했습니다. 여러 Server를 동시에 시작할 때 연결을 기다리며 멈추는 문제도 수정했습니다.

### 변경 사항

- 네이티브 MLX Runtime이 모델 호환성을 보고합니다. 가중치 행을 직접 읽을 수 있는 표준 Linear/QuantizedLinear 계층을 분산 계산합니다. 사용자 정의 계층, 변환된 가중치, MoE 전용 연산, attention, 순환 상태, KV cache는 주 노드에 유지합니다. 전체 가중치에 직접 접근하는 연산은 원래 동작을 유지하며 모델 이름별 예외를 추가하지 않습니다.
- 시각 설정을 포함하는 Qwen3.5 모델도 텍스트 로더로 TCP Ring을 사용할 수 있습니다. 분산 모드에서는 이미지 입력, GGUF, DFlash, MTP를 지원하지 않습니다. 호환성 목록은 모든 모델의 실기기 검증이나 성능 향상을 보장하지 않습니다.
- 모든 노드의 준비가 끝난 뒤 예약 포트를 해제하고 네이티브 Runtime을 시작합니다. worker가 임시 포트 예약 서비스에 잘못 연결되는 문제를 방지합니다.
- 사용 중인 호환 노드도 검색 목록에서 선택할 수 있으며 새로 고침 후에도 선택을 유지합니다. 시작 전에 중지해야 할 노드와 모델 제한을 표시하여 버튼이 비활성화된 이유를 명확히 합니다.

### 업그레이드 조건

**참여하는 모든 노드에서 Tanpopo App/Server와 MLX Runtime 전체를 업데이트해야 합니다.** 이번 Runtime은 `1.5.0-mlxswiftlm-3.31.4-gguf-dflash2-mtp-mmap-fastgguf-cache12-rdma5`이며 이전 `rdma4`와 함께 사용할 수 없습니다. 모든 노드에 동일한 배포 패키지의 Runtime과 동일한 모델 파일이 필요합니다. 버전 이름이 같다는 이유만으로 핸드셰이크를 통과하지는 않습니다.

build 0108 사용자는 **업데이트 후 재시작**을 사용할 수 있습니다. 모델 API IP 허용 목록만 켜져 있다면 각 Mac의 Tanpopo 창이나 loopback 관리 페이지에서 업데이트하세요. 다른 컴퓨터에서 업데이트하려면 관리자 인증을 켜고 로그인해야 합니다. 업데이트 후 노드를 다시 검색하고 선택하여 페어링하세요. 자세한 내용은 중국어 번체로 작성된 [자동 업데이트 가이드](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1052/docs/APP-UPDATE.md)와 [분산 추론 가이드](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1052/docs/MLX-RDMA.md)를 참고하세요.

### 검증 범위

- Go 클러스터/Runtime 관리/API 및 프런트엔드 Smoke 검사를 통과했습니다. 독립 Server 3개의 검색, 준비, 시작, 중지를 확인했습니다.
- 네이티브 3 rank collective, 소형 Llama/Qwen2/Qwen3/Qwen3.5/Qwen3.5Text 모델, 긴 프롬프트, 스트리밍, 동시 실행 제한, 취소, 재시작 Smoke 검사를 통과했습니다.
- 실제 Qwen3.5-4B를 하나의 Mac에서 독립 Server 2개로 실행하여 선형 계층 248개를 분할했습니다. 영어와 중국어 응답 및 token 수가 단일 노드 추론과 일치했으며 스트리밍과 종료 정리도 통과했습니다.
- Qwen3-0.6B는 이전 `rdma4`에서 실제 Mac 2대 간 TCP Ring 검증을 완료했습니다. 이번 버전의 Qwen3.5 실제 Mac 2대 실행과 Thunderbolt RDMA/JACCL은 아직 검증이 필요합니다. 한 대에서의 모의 실행을 해당 항목의 검증으로 간주하지 않습니다.
- macOS DMG는 서명, Apple 공증, Gatekeeper, 격리 업데이트 Smoke를 통과했습니다. 세 플랫폼의 주 프로그램을 빌드했지만 Windows MSI/UAC 및 Linux ZIP 전체 설치는 해당 OS에서 검증해야 합니다.
