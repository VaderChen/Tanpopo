# Tanpopo 1.26.0829 build 1210

## 主要更新

- Apple Silicon 的 `mlx-server` 可直接載入 GGUF，並與原生 MLX 模型依格式分群；Runtime 尚未明確回報支援的語言模型會顯示在可選取的「尚未測試（N）」群組，啟動後由 Runtime 實際驗證相容性。
- 更新內建 `mlx-swift-lm` 至 3.31.4 相容基礎，修正 Gemma 4 多模態模型共用 KV Layer 建構，改善模型型別能力回報與載入失敗訊息；保留 Vision 設定但缺少 Processor 檔案的衍生 checkpoint 會退回文字模型載入。
- 新增 MLX safetensors／GGUF MMap 路徑與記憶體保留目標；llama-server 使用 `--load-mode mmap` 與 `--fit-target`，mlx-server 使用檔案映射頁面及 MLX 配置目標。保留值不是硬性記憶體上限。
- llama-server 與 mlx-server 都可選擇 KV Cache Q8／Q4；執行狀態頁以獨立 Switch 決定是否套用，並與 DFlash 強制互斥。
- DFlash、MMap 與 KV Cache 量化集中在「進階設定」泡泡，保留 Runtime 能力與模型配對檢查。
- 模型啟動會立即顯示載入提示，說明大型模型可能需要轉換；Runtime 測試會顯示動畫視窗，完成後回報輸入／輸出 Token、生成速度及測試時間，並改善載入中、健康檢查、逾時與連線錯誤判斷。
- 主頁重新整理顯示小型進度視窗；日誌預設收合，並改善控制項高度、系統設定側欄定位及鍵盤複製貼上。
- 常用模型 JSON 清單依 GGUF／MLX 與 8B、30B、70B 以上分群，群內按名稱排序，並更新較新的大型模型項目。
- 改善大型 Hugging Face 下載、手動欄位輸入、跨語系文字與模型／mmproj 自動配對。
- `run.command` 會先經由 `build.command --runtime` 檢查版本與原始碼新舊，避免同版本的舊 prebuilt Runtime 被重複使用。

## 注意事項

- MMap 主要降低載入尖峰並讓模型權重成為可回收的檔案頁面，不保證執行期間顯示的記憶體用量一定下降；實際效果取決於檔案對齊、模型格式、儲存裝置與頁面壓力。
- mlx-server 目前回報可直載 Gemma、Llama、Mimo、MiniCPM、Mistral、Qwen2、Qwen3、Qwen3.5 與 SmolLM3 GGUF。其他有效語言模型會保留在可選取的「尚未測試」群組，由 Runtime 實際嘗試載入；若組態、權重映射或 Processor 不相容，會回報啟動失敗原因。
