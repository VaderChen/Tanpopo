## 繁體中文

### 叢集與效能

TCP Ring 的通用線性層分片擴展至 GGUF／Fast GGUF，以及相容的 DFlash／MTP。草稿由主節點產生，Target 驗證走叢集；遠端缺少模型時，沿用完整內容核對與獨立副本同步。修正 BF16 圖片投影在分片後的加總順序、壓縮權重的延遲讀取，以及工作節點的模型資產路徑。

減少控制張量、worker 零值張量、模型雜湊、日誌、GGUF metadata 與模型索引的重複配置及查詢。聊天改用共用 HTTP 連線池，SSE 分段解析避免反覆掃描，已排版的思考內容不再隨答案重排；原生 IP 白名單在策略載入時預先解析。README GIF 與操作文件同步更新。

固定函式基準的耗時約減少：模型索引 **89%**、GGUF metadata **72%**、大型 SSE 事件 **94%**、本機 HTTP 連線池基準 **66%**。這些數字不是整體模型推論加速比例；一般短 SSE 事件未觀察到改善。前輪同機雙 Rank 的兩個指定 48 Token 案例耗時減少約 **26–28%**，仍慢於單機，不能外推為 Wi-Fi 或 RDMA 加速。

### 驗證與升級

`rdma11` 已通過 Go／race、24 項前端測試、61 項 Swift 測試、12 組架構／量化 Smoke 與三節點服務流程；3 項需額外資料的 Swift 診斷測試依條件略過。本輪 Qwen3、Qwen3.5 GGUF 圖片及 DFlash 共 **26 筆實際生成請求**通過單機／叢集與 SSE 比對。另提供前輪 `rdma9`／`rdma10` 的 GGUF、Fast GGUF、DFlash1／2、MTP 六組 55 筆驗證紀錄，保留各自版本及條件。

**所有 Mac 請更新完整 App／Server 與同一份 `rdma11` Runtime，再重新配對。** 可在「系統設定 → 關於」按「更新並重新啟動」，或下載下方安裝包。模型分散推論限 Apple Silicon macOS；Windows／Linux 套件包含 Go／網頁改善與 llama-server，完整安裝仍需對應平台驗收。

探索與模型同步適用信任的區網。DFlash 仍需 safetensors Target 與相容 Draft；獨立 Fast GGUF 尚不支援內嵌 MTP，須保留原 GGUF。Draft、KV、特殊層及首次轉換仍占用本機資源，註冊不等於每個 checkpoint 都已驗證。實體 Wi-Fi 長請求問題與 Thunderbolt RDMA 尚未完成驗收。若更新後遇到先前的 `No route to host`，請完整結束 App，再從「應用程式」重新開啟。

## English

### Clustering and performance

TCP Ring's generic linear sharding now covers GGUF/Fast GGUF and compatible DFlash/MTP configurations. The coordinator generates drafts; target verification uses the cluster. Missing models use the existing full-content verification and separate-copy synchronization. Fixes preserve BF16 image-projection reduction order after sharding, lazy reads of compressed weights, and worker model-asset paths.

The update reduces repeated allocations and lookups in control tensors, worker zero tensors, model hashing, logs, GGUF metadata and model indexes. Chat reuses an HTTP connection pool; SSE parsing avoids rescanning accumulated events, and unchanged reasoning is no longer rendered with every answer update. Native IP rules are parsed when the policy loads. The README GIF and guides are refreshed.

Measured function durations fell by approximately **89%** for model indexes, **72%** for GGUF metadata, **94%** for large SSE events and **66%** in a local HTTP pooling benchmark. These are not whole-model inference speedups; ordinary short SSE events showed no improvement. Two specified 48-token cases in the earlier same-Mac, two-rank benchmark improved by **26–28%**, but remained slower than one rank. This does not establish Wi-Fi or RDMA acceleration.

### Validation and upgrading

`rdma11` passed Go/race checks, 24 frontend tests, 61 Swift tests, 12 architecture/quantization smoke fixtures and the three-node service workflow. Three Swift diagnostics requiring additional inputs were conditionally skipped. This round verified **26 real generation requests** across Qwen3, Qwen3.5 GGUF with images and DFlash, comparing single-node, cluster and SSE results. Earlier `rdma9`/`rdma10` reports retain their separate six-case, 55-request GGUF, Fast GGUF, DFlash1/2 and MTP evidence.

**Update every Mac's complete App/Server and install the same `rdma11` Runtime, then pair again.** Use **System settings → About → Update and restart**, or the installers below. Distributed MLX inference requires Apple Silicon macOS. Windows/Linux packages include the Go/web improvements and llama-server; full installation still requires validation on those platforms.

Discovery and model synchronization are for trusted LANs. DFlash still needs a safetensors target and compatible draft. Standalone Fast GGUF does not preserve embedded MTP; keep the original GGUF. Drafts, KV, specialized layers and initial conversion still require local resources. Registry membership is not certification of every checkpoint. Physical Wi-Fi long-request issues and Thunderbolt RDMA remain unverified. If the previously observed `No route to host` follows an update, fully quit and reopen the app from Applications.

## 日本語

### クラスタと性能

TCP Ring の共通線形層分割を GGUF／Fast GGUF と、互換性のある DFlash／MTP 構成へ拡張しました。開始ノードが Draft を生成し、Target の検証はクラスタで実行します。不足するモデルは内容全体を検証し、別のコピーとして同期します。分割後の BF16 画像投影の加算順序、圧縮重みの遅延読み込み、worker のモデル資産パスを修正しました。

制御テンソル、worker のゼロテンソル、モデルハッシュ、ログ、GGUF metadata、モデル索引の重複処理を削減しました。チャットは HTTP 接続プールを再利用し、SSE は蓄積済みイベントの再走査を避けます。変更のない思考内容は再描画せず、IP ルールはポリシー読み込み時に解析します。README の GIF と操作ガイドも更新しました。

固定条件の関数ベンチマークでは、所要時間がモデル索引で約 **89%**、GGUF metadata で **72%**、大きな SSE イベントで **94%**、ローカル HTTP 接続プールで **66%** 減少しました。モデル推論全体の高速化率ではなく、通常の短い SSE イベントでは改善を確認していません。前回の同一 Mac・2 Rank・48 Token の指定 2 ケースは **26–28%** 改善しましたが、単独実行より遅いままです。Wi-Fi／RDMA の高速化を示す結果ではありません。

### 検証と更新

`rdma11` は Go／race、フロントエンド 24 件、Swift 61 件、アーキテクチャ／量子化の Smoke 12 ケース、3 ノードのサービス処理を通過しました。追加入力が必要な Swift 診断 3 件は条件付きでスキップしています。今回は Qwen3、画像付き Qwen3.5 GGUF、DFlash の **実生成 26 リクエスト**で単独／クラスタ／SSE の一致を確認しました。前回の `rdma9`／`rdma10` による GGUF、Fast GGUF、DFlash1／2、MTP の 6 ケース・55 リクエストは、それぞれの条件とバージョンを保持して公開しています。

**全 Mac の App／Server と同一の `rdma11` Runtime を更新し、再度ペアリングしてください。** 設定の About から更新・再起動するか、下記のインストーラーを使用します。分散 MLX 推論は Apple Silicon macOS 専用です。Windows／Linux には Go／Web の改善と llama-server を含みますが、完全なインストールは各 OS での実機検証が必要です。

探索とモデル同期は信頼できる LAN で使用してください。DFlash は safetensors Target と互換 Draft が必要です。独立 Fast GGUF は内蔵 MTP を保持しないため、元の GGUF を残してください。Draft、KV、特殊層、初回変換にはローカル資源が必要です。登録済みでも全 checkpoint の動作保証ではありません。実機 Wi-Fi の長時間リクエスト問題と Thunderbolt RDMA は未検証です。更新後に既知の `No route to host` が出る場合は、App を完全に終了し、「アプリケーション」から開き直してください。

## 한국어

### 클러스터와 성능

TCP Ring의 공통 선형 계층 분할을 GGUF／Fast GGUF와 호환되는 DFlash／MTP 구성으로 확장했습니다. 시작 노드가 Draft를 생성하고 Target 검증은 클러스터에서 수행합니다. 없는 모델은 전체 내용을 검증하여 별도 복사본으로 동기화합니다. 분할 후 BF16 이미지 투영의 덧셈 순서, 압축 가중치의 지연 읽기, worker의 모델 자산 경로를 수정했습니다.

제어 텐서, worker의 영 텐서, 모델 해시, 로그, GGUF metadata, 모델 인덱스의 반복 작업을 줄였습니다. 채팅은 HTTP 연결 풀을 재사용하고 SSE는 누적 이벤트를 다시 검색하지 않습니다. 바뀌지 않은 추론 내용은 다시 렌더링하지 않으며 IP 규칙은 정책을 읽을 때 미리 분석합니다. README GIF와 사용 안내도 갱신했습니다.

고정 조건 함수 벤치마크에서 소요 시간은 모델 인덱스 약 **89%**, GGUF metadata **72%**, 큰 SSE 이벤트 **94%**, 로컬 HTTP 연결 풀 **66%** 감소했습니다. 전체 모델 추론의 속도 향상률이 아니며 일반적인 짧은 SSE 이벤트에서는 개선을 확인하지 못했습니다. 이전의 한 Mac・2 Rank・48 Token 지정 사례 두 개는 **26–28%** 개선됐지만 단일 실행보다 느렸습니다. Wi-Fi／RDMA 가속을 입증하는 결과는 아닙니다.

### 검증과 업데이트

`rdma11`은 Go／race, 프런트엔드 24개, Swift 61개, 아키텍처／양자화 Smoke 12개와 3노드 서비스 흐름을 통과했습니다. 추가 입력이 필요한 Swift 진단 3개는 조건에 따라 건너뛰었습니다. 이번에는 Qwen3, 이미지를 포함한 Qwen3.5 GGUF, DFlash의 **실제 생성 요청 26개**에서 단일／클러스터／SSE 결과 일치를 확인했습니다. 이전 `rdma9`／`rdma10`의 GGUF, Fast GGUF, DFlash1／2, MTP 6개 사례・55개 요청은 각 버전과 조건을 유지하여 공개합니다.

**모든 Mac의 전체 App／Server와 동일한 `rdma11` Runtime을 업데이트한 뒤 다시 연결하세요.** 설정의 About에서 업데이트 및 재시작을 선택하거나 아래 설치 파일을 사용하세요. 분산 MLX 추론은 Apple Silicon macOS 전용입니다. Windows／Linux에는 Go／웹 개선과 llama-server가 포함되며, 전체 설치는 해당 OS의 실제 장비에서 추가 검증이 필요합니다.

탐색과 모델 동기화는 신뢰하는 LAN에서 사용하세요. DFlash는 safetensors Target과 호환 Draft가 필요합니다. 독립 Fast GGUF에는 내장 MTP가 보존되지 않으므로 원본 GGUF를 유지해야 합니다. Draft, KV, 특수 계층과 최초 변환에는 로컬 자원이 필요합니다. 등록된 모든 checkpoint의 동작을 보장하지 않습니다. 실제 Wi-Fi의 긴 요청 문제와 Thunderbolt RDMA는 아직 검증이 완료되지 않았습니다. 업데이트 후 기존의 `No route to host` 문제가 나타나면 App을 완전히 종료하고 응용 프로그램에서 다시 여세요.
