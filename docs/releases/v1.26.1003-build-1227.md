## 繁體中文

本版修正 TCP Ring 收送佇列的執行緒競爭，改善斷線處理與故障診斷，讓叢集結束時可以看見失敗節點及實際原因。

### 變更與升級

- 修正 MLX socket 佇列及停止狀態的同步，並在啟動收送執行緒前完成 socket 設定。斷線或不可恢復的 I/O 錯誤會明確結束 Rank，交由 Server 回收整組。
- 原生 TCP 連線立即保存系統錯誤碼並附上文字說明，避免重試等待覆寫錯誤；失敗的 socket 會正確釋放，最後一次失敗不再額外等待。
- 張量運算逾時會標示 Rank、層編號、形狀、資料型別與通訊階段，區分運算交握、輸入交換及線性運算／輸出匯集。
- Server 保留本次 Runtime 的致命錯誤，將節點名稱及停止原因傳給整組成員，並顯示於叢集卡片。手動停止保持正常狀態，不套用前一次啟動的錯誤。
- 所有節點需一起更新完整 App／Server 與同一份 `rdma6` Runtime，再重新探索及配對；不可與 `rdma4`／`rdma5` 混用。請使用相同模型檔案與相對路徑，建議在各台下載相同 repository 的固定 revision。
- TCP Ring 維持 2–8 節點、safetensors 文字推論；GGUF、圖片、DFlash 與 MTP 不適用。區網通道未加密，探索僅適用可信任網路；模型 API 白名單不等於遠端管理登入。

### 驗證

Go 叢集、Runtime 管理與 API Smoke、C++ 連線錯誤／重試／socket 回收 Smoke，以及同機三個獨立 Server 的探索、推論、串流、故障與租約回收測試通過。原生三 Rank 的 FP32／FP16／BF16、Q4 與 collective Smoke 通過。ThreadSanitizer 重現修正前的佇列競爭，修正後同項測試及雙向斷線 Smoke 通過。同機兩個獨立 Server 執行 Qwen3.5-4B 真實模型，中英文回答與 Token 數比對、SSE 及停止回收通過。

發布後實測：自動更新後 HTTP／探索可用，原生 TCP 回報 `No route to host`；完整結束遠端並從「應用程式」開啟後恢復 TCP 與模型載入。Qwen3.5 的 2 Token 短串流完成，但完整非串流與串流請求仍發生 120 秒張量逾時，因此本版尚未通過實體雙 Mac 完整驗收。啟動方式差異的系統原因仍待確認。

實體雙 Mac 的 Qwen3.5 驗證紀錄及限制見 [分散推論指南](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1227/docs/MLX-RDMA.md)。Thunderbolt JACCL RDMA 尚未實測；不保證雙機加速。macOS 發行包完成簽章、公證、Gatekeeper 與隔離更新 Smoke；Windows、Linux 已建置封裝，完整安裝仍待各平台驗證。

## English

This release fixes a race in TCP Ring send/receive queues and improves disconnect handling and diagnostics so a stopped cluster identifies the failing node and its cause.

### Changes and upgrade

- Synchronize MLX socket queues and stop state, and configure sockets before starting their I/O threads. Disconnects and unrecoverable I/O errors explicitly terminate the rank so the Server can clean up the cluster.
- Native TCP connections preserve the system error immediately and include its description, preventing retry delays from overwriting it. Failed sockets are released, and the final failed attempt no longer adds an unnecessary delay.
- Tensor timeouts identify the rank, layer, shape, dtype, and phase: operation handshake, input exchange, or linear computation/output gathering.
- The Server retains fatal errors from the current Runtime launch and forwards the node name and stop reason to all cluster members for display in the cluster card. Manual stops remain normal and do not reuse errors from a previous launch.
- Update the complete App/Server and identical `rdma6` Runtime on every node, then discover and pair again. Do not mix with `rdma4`/`rdma5`. Use identical model files and relative paths; downloading a pinned revision of the same repository on each Mac is recommended.
- TCP Ring remains limited to 2–8 nodes and safetensors text inference; GGUF, images, DFlash, and MTP are excluded. LAN traffic is unencrypted and discovery is for trusted networks. The model API IP allowlist does not grant remote administrator access.

### Validation

Go cluster, Runtime management, and API smoke tests passed, as did C++ connection error, retry, and socket cleanup tests. Three independent Servers on one Mac passed discovery, inference, streaming, failure recovery, and lease cleanup. Native three-rank FP32/FP16/BF16, Q4, and collective smoke tests passed. ThreadSanitizer reproduced the original queue race; the same test and bidirectional disconnect smoke passed after the fix. Two independent Servers on one Mac passed real Qwen3.5-4B English/Chinese output and token comparisons, SSE, and stop cleanup.

Post-release testing: HTTP/discovery worked after automatic updating, but native TCP reported `No route to host`. Fully quitting the remote app and reopening it from Applications restored TCP and model loading. A two-token Qwen3.5 stream completed, but full non-streaming and streaming requests still hit 120-second tensor timeouts. This version has not passed complete physical two-Mac validation. The system cause of the launch-path difference remains unconfirmed.

See the [distributed inference guide](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1227/docs/MLX-RDMA.md) in Traditional Chinese for the physical two-Mac Qwen3.5 test record and limits. Thunderbolt JACCL RDMA remains untested, and two-node speedups are not guaranteed. macOS packages passed signing, notarization, Gatekeeper, and isolated update smoke tests. Windows and Linux packages were built; full installation still requires validation on those platforms.

- `Tanpopo-1.26.1003-build-1227-x64.msi`: Windows x64.

## 日本語

本版では TCP Ring の送受信キューの競合を修正し、切断処理と障害診断を改善しました。クラスタ終了時に障害が発生したノードと原因を確認できます。

### 変更と更新条件

- MLX socket キューと停止状態を同期し、I/O スレッドの起動前に socket を設定します。切断や回復不能な I/O エラーでは Rank を明示的に終了し、Server がクラスタを回収します。
- ネイティブ TCP 接続は失敗直後のシステムエラー番号と説明を保持します。再試行の待機による上書きを防ぎ、失敗した socket を解放し、最後の失敗後の不要な待機をなくしました。
- テンソル演算のタイムアウトには Rank、層番号、形状、データ型と処理段階を表示します。演算ハンドシェイク、入力交換、線形演算／出力集約を区別できます。
- Server は今回起動した Runtime の致命的エラーを保持し、ノード名と停止理由を全メンバーへ通知してクラスタカードに表示します。手動停止は正常として扱い、前回の起動エラーを流用しません。
- 全ノードの App/Server と同一の `rdma6` Runtime を更新し、再検索・ペアリングしてください。`rdma4`／`rdma5` との混在はできません。同一のモデルファイルと相対パスが必要です。各 Mac で同じ repository の固定 revision を取得することを推奨します。
- TCP Ring は引き続き 2–8 ノードの safetensors テキスト推論に対応します。GGUF、画像、DFlash、MTP は対象外です。LAN 通信は暗号化されないため、信頼できるネットワークで利用してください。モデル API の IP 許可リストはリモート管理者アクセスを許可するものではありません。

### 検証

Go のクラスタ・Runtime 管理・API、C++ の接続エラー・再試行・socket 解放の Smoke テストに合格しました。同一 Mac 上の独立した 3 Server で探索、推論、ストリーミング、障害回復、リース回収を確認し、ネイティブ 3 Rank の FP32／FP16／BF16、Q4、collective テストも合格しました。ThreadSanitizer で修正前のキュー競合を再現し、修正後は同じテストと双方向切断 Smoke に合格しました。同一 Mac 上の独立した 2 Server で実際の Qwen3.5-4B モデルを実行し、英語・中国語の出力と Token 数、SSE、停止回収を確認しました。

公開後の実測：自動更新後は HTTP／探索が動作しましたが、ネイティブ TCP は `No route to host` を返しました。リモート App を完全終了し、「アプリケーション」から開くと TCP とモデル読み込みが復旧しました。Qwen3.5 の 2 Token の短いストリームは完了しましたが、通常・ストリームの完全なリクエストは引き続き 120 秒のテンソルタイムアウトになりました。本版の実機 2 台による完全な検証は未完了で、起動方法による差のシステム内部原因も未確認です。

実機 2 台の Mac による Qwen3.5 の検証記録と制限は、繁体字中国語の [分散推論ガイド](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1227/docs/MLX-RDMA.md) を参照してください。Thunderbolt JACCL RDMA は未実測で、2 台構成での高速化は保証しません。macOS パッケージは署名、公証、Gatekeeper、隔離環境での更新 Smoke に合格しました。Windows と Linux はビルド・パッケージ作成済みですが、実環境での完全なインストール検証は未完了です。

## 한국어

이번 릴리스는 TCP Ring 송수신 큐의 경쟁 상태를 수정하고 연결 끊김 처리와 진단을 개선하여 클러스터 종료 시 실패한 노드와 원인을 확인할 수 있게 합니다.

### 변경 사항과 업데이트 조건

- MLX socket 큐와 종료 상태를 동기화하고 I/O 스레드 시작 전에 socket을 설정합니다. 연결이 끊기거나 복구할 수 없는 I/O 오류가 발생하면 Rank를 명시적으로 종료하여 Server가 클러스터를 정리합니다.
- 네이티브 TCP 연결은 실패 직후의 시스템 오류 코드와 설명을 보존합니다. 재시도 대기가 오류를 덮어쓰지 않으며, 실패한 socket을 해제하고 마지막 실패 뒤의 불필요한 대기를 없앴습니다.
- 텐서 연산 시간 초과에는 Rank, 레이어 번호, 형태, 데이터 형식과 처리 단계를 표시합니다. 연산 핸드셰이크, 입력 교환, 선형 연산/출력 수집을 구분합니다.
- Server는 현재 실행에서 발생한 Runtime의 치명적 오류를 보존하고 노드 이름과 종료 원인을 모든 구성원에게 전달하여 클러스터 카드에 표시합니다. 수동 종료는 정상으로 처리하고 이전 실행의 오류를 재사용하지 않습니다.
- 모든 노드의 App/Server와 동일한 `rdma6` Runtime을 업데이트한 뒤 다시 검색하고 페어링하세요. `rdma4`/`rdma5`와 혼용할 수 없습니다. 동일한 모델 파일과 상대 경로가 필요하며, 각 Mac에서 같은 repository의 고정 revision을 다운로드하는 방법을 권장합니다.
- TCP Ring은 계속 2–8개 노드의 safetensors 텍스트 추론을 지원합니다. GGUF, 이미지, DFlash, MTP는 제외됩니다. LAN 통신은 암호화되지 않으므로 신뢰할 수 있는 네트워크에서 사용하세요. 모델 API IP 허용 목록은 원격 관리자 권한을 부여하지 않습니다.

### 검증

Go 클러스터·Runtime 관리·API, C++ 연결 오류·재시도·socket 정리 Smoke 테스트를 통과했습니다. 한 Mac의 독립 Server 3개에서 검색, 추론, 스트리밍, 장애 복구, 임대 정리를 확인했고, 네이티브 3 Rank의 FP32/FP16/BF16, Q4, collective 테스트도 통과했습니다. ThreadSanitizer로 수정 전 큐 경쟁을 재현했고, 수정 후 같은 테스트와 양방향 연결 끊김 Smoke를 통과했습니다. 한 Mac의 독립 Server 2개에서 실제 Qwen3.5-4B 모델의 영어·중국어 출력과 Token 수 비교, SSE, 종료 정리를 확인했습니다.

출시 후 실측: 자동 업데이트 뒤 HTTP/검색은 동작했지만 네이티브 TCP가 `No route to host`를 반환했습니다. 원격 App을 완전히 종료하고 응용 프로그램에서 다시 열자 TCP와 모델 로딩이 복구되었습니다. Qwen3.5의 2 Token 짧은 스트림은 완료했으나 전체 일반·스트리밍 요청은 여전히 120초 텐서 시간 초과가 발생했습니다. 이 버전은 실제 Mac 두 대의 전체 검증을 통과하지 못했으며 시작 방식에 따른 차이의 시스템 내부 원인도 아직 확인되지 않았습니다.

실제 Mac 두 대의 Qwen3.5 검증 기록과 제약은 중국어 번체 [분산 추론 가이드](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1227/docs/MLX-RDMA.md)를 참고하세요. Thunderbolt JACCL RDMA는 아직 실측하지 않았으며 두 노드의 속도 향상을 보장하지 않습니다. macOS 패키지는 서명, 공증, Gatekeeper, 격리된 업데이트 Smoke를 통과했습니다. Windows와 Linux 패키지는 빌드했으며 전체 설치는 해당 플랫폼에서 추가 검증이 필요합니다.
