## Highlights

- Fixed delayed detection of disconnected API clients in the Apple Silicon MLX runtime. HTTP connections remain readable while a response is pending, allowing cancellation to reach the corresponding input preparation, Prefill, and generation work.
- Added request-scoped cancellation shared across HTTP handling and generation tasks. Canceling one request does not stop the runtime or cancel other users' requests; GPU work already submitted must finish before cleanup completes.
- Streaming requests now establish SSE after request validation and admission, without waiting for Tokenization or Prefill. SSE keep-alive comments are sent on connection establishment and every 10 seconds while the response remains open. Generated text continues to stream as it becomes available.
- Improved long-input handling with chunked Prefill, checked MLX evaluation, preserved decoder state, and coordinated slicing of tokens, embeddings, masks, and position information on supported paths.
- Added context and memory-budget checks based on model metadata and device limits. Supported paths can reduce the current request's Prefill chunk size without truncating the input or changing saved settings or calibration results.
- Added per-request memory reservations and a four-request limit for the current stage of multi-user MLX support. A fifth generation request receives HTTP 429; memory constraints may also reject a request before all slots are occupied.
- Improved error reporting: non-streaming context or estimated-memory violations return HTTP 413, runtime memory-pressure violations return HTTP 503, and errors after SSE starts are reported through SSE error events rather than successful completion.
- Preserved HTTP/1 response ordering and Keep-Alive support with bounded per-connection request buffering. Updated the runtime specification and general API troubleshooting documentation.

## Usage notes

- These inference changes apply to the Apple Silicon `mlx-server` runtime. Restart the model service after upgrading so an already-running process uses the updated executable.
- SSE keep-alive comments and the initial assistant-role chunk are not generated answer text. They keep the connection observable during input processing but do not eliminate long-context time to first token.
- Cancellation stops subsequent Prefill chunks and generation iterations. Already-submitted GPU work must drain, and overall GPU utilization may remain elevated if other requests or applications are active.
- Multi-user capacity remains subject to available memory and model requirements; four arbitrary maximum-length contexts are not guaranteed to fit simultaneously.
- Syntax and Release-configuration compilation checks passed. This does not constitute exhaustive inference, concurrency, or HTTP pipelining validation.
