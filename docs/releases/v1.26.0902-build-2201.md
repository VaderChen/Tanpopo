## Highlights

- The single-model Apple Silicon MLX runtime now falls back to its currently loaded model when a client omits `model`, leaves it blank, or supplies an unknown or stale model name. Chat Completion and Completion share this behavior across JSON and streaming responses, which report the actual model ID. This does not load or switch models, and request-format, security, and resource checks remain in effect.
- Corrected macOS RAM reporting to exclude file-backed cache and purgeable pages while retaining wired memory and the physical memory occupied by the compressor. Missing, malformed, or inconsistent memory counters are treated as unavailable instead of producing a misleading percentage.
- Separated the available-memory reading used by pre-launch protection from the displayed RAM percentage. Existing memory-reserve rules, MLX request budgets, and the current four-request concurrency limit remain unchanged. Linux retains its `MemAvailable`-based calculation.
- Updated the English default README, Traditional Chinese documentation, MLX runtime specification, model-name troubleshooting, and system memory metric definitions.

## Usage notes

- Restart Tanpopo after upgrading to activate the corrected management-service RAM metric. Restart the model service as well if an older mlx-server process remains running.
- Model-name fallback applies to mlx-server. Use `/models` or `/v1/models` to discover the loaded model; select and load a different model in Tanpopo when needed.
- The bottom MEMORY indicator reports whole-system RAM usage, not per-model memory or the operating system's memory-pressure level. Sampling times and rounding can still produce small differences between monitoring tools.
- Go compilation and Swift syntax checks passed. No additional inference or performance tests were run for this release.
