## 繁體中文

TCP Ring 現在由發起端統一準備模型。遠端會切換原有單機服務；已有相同內容就直接載入，缺少或內容不同時向發起端下載獨立副本，驗證完整權重、設定與 Tokenizer 後再啟動。資料夾名稱可以不同，原檔會保留，介面提供各節點進度與取消。

通用線性層分片擴大至原生註冊表中的 safetensors 文字／影像模型。聊天 API 可傳送文字與 base64 圖片。修正 macOS 路徑別名造成相同模型被誤判為不同內容的問題。

同機三個獨立 Server 的自動同步、推論、SSE、故障與租約回收，以及 Qwen3.5-4B 真實圖片的單機／雙節點回答與 Token 數比對均通過。GGUF／Fast GGUF、DFlash、MTP 尚不支援；特殊層與專家運算仍由主節點負擔。註冊不代表所有 checkpoint 都已驗證，先前實體 Wi-Fi 長請求問題與 Thunderbolt RDMA 仍待驗收。

**所有節點請更新完整 App／Server 與同一份 `rdma8` Runtime，再重新配對。** 舊版 Server 不支援此模型同步協定。此模式適用信任的區網；開啟探索即允許已探索節點邀請本機切換服務與同步模型。若更新後遇到先前的 `No route to host`，請完整結束 App，再從「應用程式」重新開啟。

[操作與驗證紀錄](https://github.com/VaderChen/Tanpopo/blob/v1.26.1003-build-1405/docs/MLX-RDMA.md)

## English

The coordinator now prepares the TCP Ring model for every node. Peers switch their existing standalone service, reuse an identical local copy, or download a separate copy from the coordinator when missing or different. Full weights, configuration and tokenizer files are verified before startup. Folder names may differ; original files are preserved, with per-node progress and cancellation.

Generic linear sharding now includes registered safetensors text and vision models. The chat API accepts text and base64 image parts. macOS path aliases no longer cause identical model contents to fail verification.

Three independent Servers on one Mac passed synchronization, inference, SSE and lifecycle smoke tests. Real Qwen3.5-4B image input produced identical answers and token counts in single-node and two-node tests. GGUF/Fast GGUF, DFlash and MTP remain unsupported; specialized layers and expert operations stay on the coordinator. Registry membership is not certification of every checkpoint. Physical Wi-Fi long-request issues and Thunderbolt RDMA remain unverified.

**Update every App/Server and install the same `rdma8` Runtime, then pair again.** Older Servers cannot use model synchronization. Discovery is for trusted LANs and permits discovered peers to request a service switch and model synchronization. If an update is followed by the previously observed `No route to host`, fully quit and reopen the app from Applications.

## 日本語

TCP Ring の開始ノードが全ノードのモデルを準備します。各ノードは既存の単独サービスを切り替え、内容が同じローカルコピーを再利用します。モデルがない、または内容が異なる場合は開始ノードから別のコピーをダウンロードし、重み・設定・Tokenizer を検証してから起動します。フォルダー名は一致しなくてもよく、元のファイルを保持します。進捗表示とキャンセルにも対応します。

共通の線形層分割を、登録済みの safetensors テキスト／画像モデルへ拡張しました。チャット API は base64 画像に対応します。macOS のパス別名による内容検証の誤判定も修正しました。

同一 Mac 上の独立した 3 Server による同期・推論・SSE・終了処理、および実際の Qwen3.5-4B 画像入力の単独／2 ノード出力比較が通過しました。GGUF／Fast GGUF、DFlash、MTP は未対応です。特殊層とエキスパート演算は開始ノードに残ります。全 checkpoint の動作、実機 Wi-Fi の長時間リクエスト問題、Thunderbolt RDMA の検証完了を意味しません。

**全ノードの App／Server と同一の `rdma8` Runtime を更新し、再度ペアリングしてください。** 信頼できる LAN で使用してください。探索を有効にすると、発見されたノードからのサービス切り替えとモデル同期の招待を受け付けます。更新後に `No route to host` が出る場合は、App を完全に終了して「アプリケーション」から開き直してください。

## 한국어

이제 시작 노드가 TCP Ring 전체의 모델을 준비합니다. 각 노드는 기존 단독 서비스를 전환하고 내용이 같은 로컬 복사본을 재사용합니다. 모델이 없거나 내용이 다르면 시작 노드에서 별도 복사본을 다운로드하여 가중치, 설정, Tokenizer를 검증한 뒤 시작합니다. 폴더 이름은 달라도 되며 원본 파일을 보존합니다. 노드별 진행 상황과 취소 기능을 제공합니다.

공통 선형 계층 분할을 등록된 safetensors 텍스트／이미지 모델로 확장했습니다. 채팅 API에서 base64 이미지를 사용할 수 있으며, macOS 경로 별칭 때문에 같은 모델을 다르게 판단하던 문제를 수정했습니다.

한 Mac의 독립적인 Server 3개로 동기화, 추론, SSE, 종료 처리를 검증했습니다. 실제 Qwen3.5-4B 이미지 입력의 단일／2노드 답변과 Token 수도 일치했습니다. GGUF／Fast GGUF, DFlash, MTP는 아직 지원하지 않습니다. 특수 계층과 전문가 연산은 시작 노드에 남습니다. 모든 checkpoint의 검증을 의미하지 않으며 실제 Wi-Fi의 긴 요청 문제와 Thunderbolt RDMA는 추가 검증이 필요합니다.

**모든 App／Server와 동일한 `rdma8` Runtime을 업데이트한 후 다시 연결하세요.** 신뢰하는 LAN에서 사용하세요. 탐색을 켜면 발견된 노드가 서비스 전환과 모델 동기화를 요청할 수 있습니다. 업데이트 후 `No route to host`가 발생하면 App을 완전히 종료한 뒤 응용 프로그램에서 다시 여세요.
