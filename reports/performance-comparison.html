Actual product parameters

MLX+GGUF 三策略

Group 自動策略固定使用 64，除非明確指定才使用 Group 32；策略判定依來源 block 與 tensor metadata，不依模型名稱。

模式參數主要權重定位
原生MLX檔案未轉換原生 checkpointAffine 4-bit／group 64速度與品質基準
MLX + 預設快速轉換speed + auto + controlsK-Quant 重新量化為 INT8；auto 固定 group 64INT8 轉換路徑
MLX + Beta 1speed-passthrough + group 32 + controlsQ4_K 沿用來源 4-bit block；其餘張量 group 32全域 Group 32 對照
MLX + Beta 2speed-passthrough + group 64 + controlsQ4_K 沿用來源 4-bit block；其餘張量 group 64混合 Group 對照

Q4_K 沿用時每個 32 元素 sub-block 的 group 由格式決定；Beta 1／Beta 2 的差異只作用於其他需要重新量化的張量。

Experimental follow-up

Recurrent controls 量測範圍

本輪三種 GGUF 策略均使用相同的 recurrent controls 設定，避免額外變因。

固定 controls 設定

MLX + 預設快速轉換、MLX + Beta 1 與 MLX + Beta 2 均傳入 --gguf-recurrent-promotion controls； 本節只記錄測試條件，不把 recurrent promotion 的效果和三種儲存策略混為同一項比較。

Methodology

測試方法與限制

速度

  • OpenAI 相容 /v1/chat/completions
  • 46 prompt tokens、128 completion tokens
  • Temperature 0、Top-K 1、thinking 關閉
  • 暖機 1 次；正式 3 次採中位 tok/s

精度

  • OpenAI Simple Evals MMLU CSV
  • 固定 100 題、seed 0
  • 每個模型與模式使用完全相同題目
  • 關閉 thinking；輸出上限 512 tokens、單題逾時 600～900 秒
  • 只接受獨立 A、B、C、D；length 且尚無答案才排除

共同 Runtime

  • 原生 MLX 與 MLX+GGUF 均使用相同 Release build
  • MLX+GGUF 明確傳入 --mmap；原生MLX檔案未轉換模式未傳入
  • MLX+GGUF 速度量測使用已完成的永久快取
  • KV cache 上限 4096 tokens
  • 未啟用 DFlash 與 KV Cache 量化

解讀限制

  • 本輪完整四策略比較為單一模型樣本，不代表所有 GGUF 的固定結果
  • Qwen 3.5 4B Q4_0 另以 20 題確認改動前後逐題一致
  • 程序 RSS 不等於系統統一記憶體總量
  • Runtime 或 Metal 更新後應重新測試

Result notes

結果補充

原生 MLX 基準

本輪原生 MLX 為 48.863 tok/s、79／100，並占用 4.711 GiB 模型磁碟與 4.897 GiB 程序 RAM。

三種 GGUF 結果

MLX + 預設快速轉換、MLX + Beta 1、MLX + Beta 2 分別為 27.720、36.794、37.678 tok/s；正確題數為 69／100、68／100、67／99。

來源量化差異

MLX + 預設快速轉換將 K-Quant 重新量化為 INT8；MLX + Beta 1／MLX + Beta 2 沿用 Q4_K 來源 block，其他張量分別使用 Group 32／64。

適用範圍

結果只代表本次模型、Runtime 與測試條件；其他架構、量化格式或 checkpoint 需另行量測。
